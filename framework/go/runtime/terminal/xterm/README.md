# 终端状态进程

使用与 UI 相同的 `@xterm/headless 6.0.0` 解析输出，并用 `@xterm/addon-serialize 0.14.0` 序列化缓冲。`assets/state.js` 补齐同版本解析器的光标、滚动区、保存位置、字符集、模式、扩展属性、链接、调色板和未完成控制序列；该文件也由前端恢复器直接导入。

- `SessionSpec.DefaultColors` 可在 PTY 启动前设置会话默认前景、背景及光标色；OSC 查询、颜色重置、快照与进程恢复使用同一配置，程序调色板覆盖仍独立保存。
- 启用 ViewStateFactory 的 PTY 输出从创建时开始连续解析，与页面/画布生命周期无关。
- 输出与恢复游标在终端管理器同一锁内取样。普通业务观察者仍读原始 ring；只有画布请求 opt-in 恢复。
- 每个终端有独立受管状态进程。每 256 KiB 保存恢复检查点，保留之后的原始增量；辅助进程失败时恢复检查点和增量，不重启 PTY，不重复历史设备应答。
- UI 回放不会向 PTY 回写查询应答；设备查询由唯一状态所有者生成，真实输入和焦点/鼠标事件仍走既有授权和幂等链路。
- 辅助程序只有嵌入的解析代码，通过本机 stdin/stdout 通信；不给外部文本提供 eval、命令或文件访问入口。启动清除 `NODE_*` 注入变量，Windows 无控制台窗口。
- 状态进程随 PTY 读尽冻结并退出，有限历史状态仍可回读；Close 可以直接中断卡住的辅助进程。
- 默认滚动历史与 UI 同为 10000 行；超出快照传输预算时只缩减旧滚动历史，当前屏幕仍完整恢复。传输 ring 4 MiB、检查点增量约 256 KiB；状态传输最大 2 MB、控制序列最大 1 MiB、辅助 V8 堆 96 MiB。过界显式失败，保留原 PTY 和真实输入通道，不报告假恢复成功。
- 旧版数据流在状态化解析接入之前已被回收的内容不可凭空恢复。新会话从第一帧开始获得此能力。

原始库来自 npm 的锁定版本，MIT 许可保存在 `assets/LICENSE-xterm`，原始文件 SHA256 见 `assets/manifest.json`。发行脚本校验前后端版本一致，并分发固定 Node LTS 的原生 helper；不依赖目标用户额外安装 Node。

官方参考：[xterm.js 的 headless 与重连恢复说明](https://github.com/xtermjs/xterm.js#nodejs-support)。
